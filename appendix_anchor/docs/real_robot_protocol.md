# Протокол проверки на реальном манипуляторе (Green-VLA)

Задача протокола: измерить на настоящем роботе те же величины, что в AnchorBench, чтобы цифры со стенда и с робота можно было сравнить. Он рассчитан на одну сессию на 2–3 часа на той же установке, где собирались демонстрации для дообучения.

Инструменты: `real_robot/make_trial_sheet.py` генерирует рандомизированный лист проб, `real_robot/analyze_trials.py` считает метрики с доверительными интервалами Уилсона и строит графики.

## 0. Подготовка: где объекты лежали в демонстрациях

Нужен файл `my_demo_positions.csv` с колонками `object,x_cm,y_cm`: по строке на демонстрацию, положение целевого объекта на первом кадре в системе координат стола. Если координаты не логировались, их можно разметить по первому кадру каждой демонстрации: кликнуть по центру объекта и пересчитать через гомографию стола по четырём маркерам. Это нужно, чтобы считать расстояние до ближайшей обучающей позиции, которое идёт по оси X на графике P1.

```bash
python real_robot/make_trial_sheet.py --objects tape pliers screwdriver \
    --train_positions my_demo_positions.csv --table 60 40 --grid 4 3 --reps 2 --out trials.csv
```

## Пробы

| ID | Что делаем | Что меряем | Как понимать провал |
|---|---|---|---|
| P1, сетка позиций | Целевой объект ставим по сетке 4×3 по столу, остальные на свои обычные места | Успех в зависимости от расстояния до ближайшей позиции этого объекта в демо | Если успех падает с расстоянием, политика обобщает по месту, а не по объекту |
| P2, swap | Целевой объект и дистрактор меняются местами | Доля захватов дистрактора (wrong object) | Рука едет туда, где цель лежала в демо, и берёт то, что там сейчас |
| P3, пустой стол | Целевой объект убран, инструкция та же | Доля «захватов воздуха» на обычном месте цели | Прямая проверка на запоминание (как наблюдение LIBERO-PRO о захвате при подменённом объекте) |
| P4, смена инструкции | Одна и та же сцена, инструкции «возьми A» и «возьми B» | Разница конечных точек траекторий | Если траектории почти совпадают, язык на действие не влияет |
| P5, подмена точки | Точку JPM подменяем на центр дистрактора, инструкция называет цель; λ guidance ∈ {0, 0.5, 1} | Доля эпизодов, где робот следует точке, а не языку и раскладке | Если при большом λ робот редко следует точке, guidance проигрывает приору политики |

Исход записывается в лист одним словом: `success | wrong_object | miss | collision | timeout | air_at_usual_place`. Для `wrong_object` в колонку `grabbed` пишется, какой объект взят.

```bash
python real_robot/analyze_trials.py --trials trials.csv \
    --train_positions my_demo_positions.csv --out real_robot/report
```

## Как подменить точку в Green-VLA для P5

В статье JPM устроен так: VLM указывает 2D-точку (u, v), по глубине d(u, v), матрице камеры K и позе камеры T она поднимается в 3D: p* = T · d·K⁻¹[u, v, 1]ᵀ. Затем IK даёт q*, а guidance (ΠGDM) смещает поле скоростей flow-matching к траекториям, ведущим к p*. Для P5 достаточно заменить (u, v) на центр дистрактора и не трогать инструкцию. Если в используемой сборке JPM нет, можно обойтись простой заменой: смешивать предсказанный декартов шаг с единичным вектором к p* с весом λ, пока до цели дальше примерно 10 см (так сделан `guide` в AnchorBench).

## Без робота: SimplerEnv

Если доступа к установке нет, логику P1/P2 можно воспроизвести в SimplerEnv WidowX с открытыми чекпойнтами (`SberRoboticsCenter/GreenVLA-5b-stride-1-R1-bridge` и `...-R2-bridge`). Их можно загрузить через `load_pretrained_policy` из репозитория Green-VLA и сдвигать начальные позиции объектов в конфиге сцены. По литературе стоит ожидать падения успеха, когда позиции выходят за распределение Bridge (ср. LIBERO-Plus, 2602.24143).

## Как проверить саму гипотезу на Green-VLA (следующий шаг, пока не сделано)

1. **Action expert в системе координат якоря.** На этапе R1 (дообучение под конкретного робота) подавать в action expert вместо абсолютной проприоцепции позу схвата относительно p*. Для декартовых слотов unified action space это просто сдвиг, для суставных нужен IK, который в JPM уже есть.
2. **Вырезка вместо полного кадра.** Action expert получает токены вырезки вокруг проекции p* с головной камеры и токены языка. Полный кадр остаётся у VLM-планировщика и у модуля указания. В AnchorBench `af_global` с полным кадром оказался не хуже, так что этот пункт можно проверять как абляцию.
3. **Абляция `af_global`.** Тот же action expert, но с полным кадром, чтобы измерить, теряется ли обобщение, когда обходной путь снова открыт (в AnchorBench это контрольный эксперимент).
4. **Метрики:** P1–P5 до и после, плюс точность указания (доля p*, попавших в объект), чтобы разделить успех на «нашли объект» и «взяли найденное».
